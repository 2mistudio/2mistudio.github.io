Day 8: Responsive Design 響應式設計

Responsive Web Design

一、學習目標

完成本日課程後，你將能夠：

  • 理解響應式設計的概念與 viewport 設定
  • 使用 Media Query 針對不同螢幕寬度套用樣式
  • 了解 Mobile-First 與 Desktop-First 的差異
  • 使用相對單位（%、rem、vw、vh）建立彈性版面
  • 讓圖片自動適應容器大小

二、什麼是響應式設計？

響應式設計（Responsive Web Design）是讓同一份 HTML，能在手機、平板、桌機上都有合適的顯示效果。

三大核心要素：

  • 彈性版面：優先使用相對單位，而非固定像素
  • 彈性圖片：圖片隨容器縮放
  • Media Query：依螢幕條件切換 CSS 樣式

Viewport 設定：

1. 歷史的包袱：預設的 980px 畫布

在智慧型手機剛問世時，市面上只有專為電腦設計的寬網頁。為了不讓網頁排版擠成一團，手機瀏覽器採取了一個相容策略：在後台開一張約 980px 的虛擬畫布（Layout Viewport）來載入網頁，接著再將畫面等比例「微縮」塞進小小的手機螢幕裡。這導致使用者看舊網頁時，字體都像芝麻一樣小，必須用手指放大、滑動。

2. Retina 時代的挑戰：實體像素 vs 邏輯像素

現代手機普遍配備了高解析度螢幕（如 Retina 螢幕），硬體的實體像素非常多（例如寬度達 1179px）。如果網頁直接按照這個硬體數字去顯示，高密度的像素點會讓網頁上的按鈕和文字縮得更小、完全無法閱讀。

為了解決上述兩個問題，告訴瀏覽器「這是一頁做好響應式（RWD）的現代網頁」，我們必須在 HTML 的 <head> 標間之間加入這行標準設定：


<meta name="viewport" content="width=device-width, initial-scale=1.0">
  • width=device-width：寬度等於裝置螢幕寬度
  • initial-scale=1.0：初始縮放比例為 1

Media Query 媒體查詢：

常用於根據瀏覽器視窗尺寸，動態切換並套用對應的 CSS 樣式。

基本語法：


@media 媒體類型 and (條件) {
  選擇器 {
    屬性: 值;
  }
}

常用條件：

條件 說明
min-width 螢幕寬度 大於等於指定值時套用
max-width 螢幕寬度小於等於指定值時套用
orientation: portrait 直向
orientation: landscape 橫向

Media Types 媒體類型（可省略，預設為 all）：

  • screen：螢幕裝置（電腦、手機、平板等，RWD 最常用）
  • print：列印或列印預覽模式
  • all：適用於所有裝置

/* 媒體類型為螢幕，且寬度介於 768px 到 1024px 之間*/
@media screen and (min-width: 768px) and (max-width: 1024px) { }

組合條件：


/* 寬度介於 768px 到 1024px */
@media (min-width: 768px) and (max-width: 1024px) { }

/* 符合任一條件，用逗號分隔 */
@media (max-width: 480px), (orientation: portrait) { }

三、Mobile-First 還是 Desktop-First

Mobile-First（行動優先）

  • 寫法邏輯：預設樣式就是手機版，透過 @media (min-width: ...) 逐步往大螢幕（平板、桌機）疊加樣式。
  • 優點：手機載入時不需要解析一堆桌機用的冗餘樣式（效能表現比較好），且迫使開發者在有限空間內先篩選出「最核心的內容與功能」。

Desktop-First（桌機優先）

  • 寫法邏輯：預設樣式是桌機版，透過 @media (max-width: ...) 逐步把版面縮小或隱藏元素來適應小螢幕。
  • 缺點：桌機優先的手機版網頁常常只是把桌機版硬塞進小螢幕再隱藏東隱藏西，容易造成載入過多不必要的程式碼與圖片，影響手機瀏覽體驗。

Google 早從 2016 年起全面改用「行動版網頁」的內容來進行索引與排名評分 。如果網站手機載入太慢或排版出問題，在 Google 搜尋引擎上的排名就會受到負面影響。此外，手機用戶的網路環境與硬體往往不如桌機。從 Mobile-First 出發可以強迫團隊精簡資源、優化載入速度，這直接符合 Google 對網頁效能的核心指標要求。

四、常見的斷點設定 (Breakpoints)

斷點就是用來切換版面的視窗螢幕寬度。以下為常見參考值：

裝置 寬度
手機 < 576px
大手機 / 小平板 ≥ 576px
平板 ≥ 768px
小桌機 ≥ 1024px
大桌機 ≥ 1200px

建議： 斷點應依內容何時破版來決定，而非特定裝置型號。初學者一開始使用 2-3 個斷點即可（例如 768px、1024px）。

五、響應式單位

為了達到網頁最大的彈性，比起固定鎖死的絕對單位（如：像素 px）響應式頁面更常使用相對單位來控制版面。以下為常用的相對單位：

單位 說明 適用情境
% 百分比，相對於上一層 HTML 父元素（1% - 100%） 寬度、欄位
rem 相對於網頁預設字體大小（1rem = 16px） 字體、間距
vw Viewport-Width 視窗的寬度（1vw - 100vw） 滿版寬度、大標題
vh Viewport-Height 視窗的高度（1vh - 100vh） 滿版高度區塊

語法範例：


width: 50%;         /* 父元素寬度的一半 */
font-size: 1.5rem;  /* 根元素 16px 時為 24px */
width: 100vw;       /* 完整視窗寬度 */
height: 100vh;      /* 完整視窗高度 */

搭配 max-width / min-width：


.container {
  width: 90%;
  max-width: 1200px;  /* 大螢幕不要無限拉寬 */
  margin: 0 auto;
}

響應式圖片


img {
  max-width: 100%;  /* 不超出容器 */
  height: auto;     /* 維持原比例 */
}

六、程式碼範例

Mobile-First 基本寫法


/* 預設：手機版（單欄） */
.cards {
  display: grid;
  grid-template-columns: 1fr;
  gap: 16px;
}

/* 平板以上：兩欄 */
@media (min-width: 768px) {
  .cards {
    grid-template-columns: repeat(2, 1fr);
  }
}

/* 桌機以上：四欄 */
@media (min-width: 1024px) {
  .cards {
    grid-template-columns: repeat(4, 1fr);
  }
}

響應式導覽列


/* 手機：垂直排列 */
.nav {
  display: flex;
  flex-direction: column;
  gap: 10px;
}

/* 平板以上：水平排列 */
@media (min-width: 768px) {
  .nav {
    flex-direction: row;
    justify-content: space-between;
  }
}

顯示與隱藏


.menu-button {
  display: block;  /* 手機顯示 */
}

.menu-links {
  display: none;   /* 手機隱藏 */
}

@media (min-width: 768px) {
  .menu-button { display: none; }
  .menu-links  { display: flex; }
}

響應式容器與字體


html {
  font-size: 16px;
}

.container {
  width: 90%;
  max-width: 1200px;
  margin: 0 auto;
  padding: 1rem;
}

@media (min-width: 768px) {
  .container {
    padding: 2rem;
  }
}

七、常見錯誤與注意事項

錯誤 1: 忘記加 viewport meta

問題：沒有 viewport 設定時，手機會以約 980px 的寬度渲染，Media Query 看起來像是「沒有生效」。


<!-- 每個頁面都要記得加 -->
<meta name="viewport" content="width=device-width, initial-scale=1.0">

錯誤 2: 混用 min-width 與 max-width

錯誤示範：


/* ❌ 同一份 CSS 中混用兩種方向，容易互相覆蓋、難以維護 */
@media (min-width: 768px) { .box { width: 50%; } }
@media (max-width: 1024px) { .box { width: 80%; } }

正確做法：一份 CSS 只選擇一種方向（建議 Mobile-First，全部使用 min-width），並由小到大排列。

錯誤 3: Media Query 寫在基礎樣式之前

錯誤示範：


/* ❌ 後面的基礎樣式會覆蓋 Media Query */
@media (min-width: 768px) {
  .box { width: 50%; }
}

.box { width: 100%; }

正確做法：


/* ✅ 基礎樣式在前，Media Query 在後 */
.box { width: 100%; }

@media (min-width: 768px) {
  .box { width: 50%; }
}

錯誤 4: 使用 100vw 造成橫向捲軸

100vw 包含垂直捲軸的寬度，在有捲軸的頁面會比實際可視寬度多出一點，造成橫向捲動。


/* ❌ 可能出現橫向捲軸 */
.full { width: 100vw; }

/* ✅ 一般滿版用 100% 即可 */
.full { width: 100%; }

錯誤 5: 使用固定像素寬度


/* ❌ 螢幕小於 960px 時會溢出 */
.container { width: 960px; }

/* ✅ 彈性寬度 + 最大寬度 */
.container {
  width: 100%;
  max-width: 960px;
}

錯誤 6: 圖片超出容器


/* ✅ 全站圖片的基本設定 */
img {
  max-width: 100%;   /*設定最大寬度為 100%，讓圖片最大只會填滿父系元件的寬度，不會超出容器*/
  height: auto;
}

注意事項

1. 斷點數量不要過多

  • 每增加一個斷點，維護成本就增加
  • 先確保彈性版面在各種寬度都能運作，再補斷點

2. 善用相對單位，以及 Flexbox 與 Grid 的彈性

  • 相對單位可以增加介面元件的彈性，減少 Media Query 的使用量
  • flex-wrap、repeat(auto-fit, minmax()) 本身就具有響應式能力

3. 善用瀏覽器的開發者工具測試

  • 按 F12，再按「裝置工具列」圖示（或 Ctrl/Cmd + Shift + M）
  • 可模擬各種裝置尺寸，並拖曳調整寬度
  • 注意：開發者工具只是模擬實際環境，真實裝置中仍有不少情境跟問題是無法被模擬的，最理想狀態還是用真正的上網裝置來做測試

4. 手機上的 100vh

  • 手機瀏覽器的網址列會伸縮，100vh 可能比實際可視高度大
  • 新版瀏覽器提供 dvh 單位（如 100dvh）可改善此問題，了解即可

5. 延伸學習

  • 網頁會隨裝置改變大小，這正是網頁介面和傳統平面設計最不一樣的地方。因此，想學好介面設計，響應式邏輯是不可或缺的基本功。
  • 響應式設計的語法其實非常有彈性、也稍微進階，不過本篇已經為大家精選出初學者最需要知道的入門精華。讀完之後，非常推薦大家進一步延伸閱讀相關教學，讓你的響應式觀念更完整。
